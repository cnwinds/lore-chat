# 向量数据库选型决策（本地部署）

> 适用场景：教培 AI 学习产品，初期数据量不大，要求数据必须留在本地，不接受外部托管服务。

---

|------|---------|

## 二、本地部署三选一对比

| 维度 | **pgvector** | **Qdrant** | **Milvus** |
|------|-------------|-----------|-----------|
| **部署方式** | Postgres 插件 | Docker 单容器 | 多组件（etcd/MinIO/Pulsar/standalone） |
| **依赖复杂度** | 极低（有 PG 即可） | 低（单个 Docker 镜像） | 高（K8s/多容器编排） |
| **推荐向量规模** | < 500万 | 10万 – 500万 | 千万级以上 |
| **学习曲线** | 低（SQL + 向量混合） | 中（REST/gRPC API） | 高 |
| **运维负担** | 低 | 中 | 高 |
| **混合检索** | ✅ 原生支持 | ✅ 原生支持 | ✅ 2.4+ 支持 |
| **内存占用** | 随 PG 实例 | ~几百 MB | 较高 |
| **预估月成本** | 已有 PG 则 0 增量 | $0–50（自建） | $200+（自建维护） |

---

## 三、决策树

```
你有现成的 Postgres 实例吗？
├── 是 → 用 pgvector（零额外组件，SQL 查询最顺手）
└── 否 → 要不要新起一个服务？
    ├── 愿意搭个 Postgres → pgvector（生态好，后续维护简单）
    └── 倾向专用向量库 → Qdrant（Docker 一键启动，性能更好）
```

## 四、教培场景适配建议

### 资料结构特点
- **老师资料**：教案、课件、习题 → 标签丰富（学科、年级、知识点）
- **学生资料**：作业、错题、笔记 → 关联用户、时间戳

### 推荐实践
1. **元数据过滤**：用 `WHERE subject = '数学' AND grade = '高三'` 配合向量检索
2. **增量更新**：新知识入库用 upsert，不影响已有索引
3. **备份策略**：
   - pgvector：直接 `pg_dump`
   - Qdrant：挂载 volume 持久化

### 分块策略实测

> 实验时间：2026-08-18 | 关联：本文档第四节的综合建议

#### 实验背景

教培场景知识库需处理两类资料：
- **老师资料**：教案、课件、习题（长文档为主）
- **学生资料**：作业、错题、笔记（短问答为主）

不同长度文档需不同分块策略，本次对比三组参数。

#### 参数组合与结果

| 参数组合 | 效果 | 结论 |
|---------|------|------|
| 512 字，无重叠 | 召回偏低；短上下文丢失关键信息，语义完整性受损 | 不适用 |
| 512 字 + 80 字重叠 | 明显变好；短问答覆盖更完整，边界处关键信息不丢失 | 适合短问答场景 |
| 1024 字 + 150 字重叠 | 长文档表现最佳；但短问答会带入周边噪声 | 适合长文档，需配合元数据过滤降噪 |

#### 综合建议

| 场景 | 推荐参数 | 备注 |
|------|---------|------|
| 短问答（学生错题、笔记） | 512 字 + 80 字重叠 | 保证上下文完整 |
| 长文档（教案、课件） | 1024 字 + 150 字重叠 | 减少碎片化 |
| 混合场景 | 按资料类型分流 | 配合标签/元数据过滤 |

## 五、结论

| 推荐优先级 | 选型 | 理由 |
|-----------|------|------|
| ⭐⭐⭐ **首选** | **pgvector** | 若已有 Postgres，零额外组件；教学场景天然有结构化字段，SQL+向量混合查询最顺手 |
| ⭐⭐⭐ **备选** | **Qdrant** | Docker 单机即可，性能极致，复杂过滤强；适合无 PG 基础的场景 |
| ⭐ 暂不推荐 | **Milvus** | 架构过重，当前规模无需分布式；数据破千万再迁移 |
