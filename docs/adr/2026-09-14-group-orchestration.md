# ADR 2026-09-14：群舞台上的协调者与工人

## 状态

已采纳（2026-09-14）。补强 [ADR 2026-09-12](2026-09-12-role-rooms.md) 与 [ADR 2026-09-13 group-as-stage](2026-09-13-group-as-stage.md)。产品展开见 [product-role-rooms.md](../product/role-rooms.md)。

## 背景

群已经是唯一完整现场：`@谁` 谁应，点名交棒，工人用人设与自己的沙箱，发言留在本群。缺的是分工账本——协调者拆给多人会被第一次 `end_turn` 掐断；工人回执若不 @ 协调者就收不齐；超时无人追问。

## 决策

1. **本轮协调者 = 主人在本群点名的角色。** 不设固定群主。一对一 `peer_dm` 委托不变。
2. **工人借用该角色的执行体（人设 + 沙箱），舞台仍是本群。** 禁止为群内派工另开 `peer_dm`。
3. **Assignment 账本挂在 Delivery 后面，不新开工具。** 群里 `send_message(expect_reply)` 点名他人则开账；被派者再在本群 `send_message` 则结账并唤醒 assigner（即使正文没 @）。
4. **同轮可并行多条 `send_message`。** 同一房间的贴消息在 Delivery 内串行；hop 共用 `N+1`。本批派完再交棒。群内开回合仍串行（房间锁）。
5. **超时只叫醒协调者。** 可选 `due_in_minutes`，省略则从工人真正开回合起算默认时长。调度环把逾期账记为已询问，系统刺激唤醒 assigner，由他用自己的声音追问。禁止系统假扮协调者，不打断工人正在跑的沙箱。
6. **征询续聊 ≠ 点名交棒。** 未回答的 `ask_user`（及沙箱确认）把主人下一句绑在提问者身上，即使正文没有 `@`。点选选项时正文只带所选文案，用结构化 mentions 唤醒提问者。正文里再 `@` 提问者也不算新的协调者点名；只有 `@` 了别人，才是新的点名。

Wake 策略（群）在原「仅 mentions」上加：工人回执 → assigner；逾期系统刺激 → assigner；未答征询 → 提问者。

## 明确不采用

- 工人飞到 `peer_dm` 再把摘要转回群
- 协调者回合里嵌套 subagent
- 为群另做思考者
- 固定群主角色
- 超时由系统冒充协调者发言，或重复刷屏
