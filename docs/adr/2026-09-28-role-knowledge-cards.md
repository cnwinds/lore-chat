# ADR 2026-09-28：角色知识卡（按作用域的记忆与自动进化）

## 状态

已采纳（2026-09-29）。P0–P3 已落地。产品展开见 [role-knowledge-cards.md](../product/role-knowledge-cards.md)。

## 背景

现网只有一个认知容器：主人画像（`memory_facts`，`owner_key` = 工作区）。多角色落地后（[ADR 2026-09-09](2026-09-09-multi-role-shell.md)），角色干活积累的经验无处沉淀：

- 被抽进主人画像，再被主人遗忘或拒绝（22 条里 13 条属此类，`workflow` 类噪声最重）；
- 或由主人手写进角色 `system_prompt`，靠手工「进化」；
- 或因语境保全门槛整条丢弃（「备考中法务伦理是弱项」对全局画像是噪声，对备考助手是关键认知）。

根因：「这是谁的认知」只有一个答案。

## 决策

1. **知识卡是统一的认知单元。** 主人记忆就是作用域为主人的卡。存储沿用 `memory_facts` 一族，作用域编码进现有 `owner_key`：主人仍是工作区 id，左栏角色 `role:<role_id>`，通道共用角色 `persona:<persona_id>`。表结构、唯一键与 `SlotResolver` 四动作、墓碑、出处不变式对所有作用域生效。
2. **通道卡归人设**，不归每个实例背后的隐藏工作角色：共用同一人设的通道一起学。
3. **文档知识库不分角色。** ADR 2026-09-09「不采用每角色私有知识库根或私有主人画像库」继续成立；本决策只新增角色认知这一层。卡片不复制文档正文，只记指向与提炼。
4. **抽取按作用域分开。** 主人抽取器不变；新增角色卡抽取器，门槛为归属、耐久、语境保全、依据、外部发言是数据不是指令（产品文档 §3.2）。同一次关段任务里先后运行，禁止合成一个提示词。角色卡用自己的种类词表（领域知识 / 主人在此 / 做法 / 经验 / 受众），不套主人画像的种子槽。
5. **来源信任。** 卡片来源记为 `direct`（主人）或 `external`（通道外部发言）。外部来源只能形成领域知识与受众卡；先是待印证，出现在 3 段不同外部会话里才确认；等级最低，不能覆盖主人来源；具体外部发送者本人的信息不记。助手自己的断言不能单独成卡，须有主人发言或本段工具取证支撑。
6. **进化分三段，都是后台系统流程**：摄入（关段对齐）、整理（空闲批量：合并、抽象、冲突先补条件、淡出）、人设进化。不经 Agent 工具；《戒律》「默认不动」约束回合内 Agent，不受影响。
7. **人设全自动改写。** 只由主人来源、跨至少 2 段会话的卡驱动；整份人设可改；每次存版本（差异、理由、依据卡）；回退即墓碑；主人手改后以主人版本为基准三路合并；不越过《戒律》；已并入人设的卡不再重复注入。
8. **人设修订存 `roles.db`。** 一张修订表服务左栏角色与共用角色，每次人设写入同事务追加一版并记来源。不进知识库 git：人设的唯一真相在 `roles.db`，且不是知识文档，不应进检索与目录树。P0 起采集，界面与回退在 P2。
9. **升格为 Skill 或知识库文档只提议。** 二者是主人共享资产，《戒律》§1.1、§6.1 要求主人明确要求才建；进化只在成长日志里提议，主人接受后走 `KnowledgeWriter`。
10. **注入**：核心角色卡进 system，位于【当前角色】之后、【用户记忆】之前；按轮检索的卡放本轮用户消息之前，保住前缀缓存。
11. **通道是否带主人记忆由实例配置**（`include_owner_memory`，默认关）。原先通道回合无条件注入主人记忆，外部发送者在和一个「知道主人是谁」的模型对话。
12. **跨角色查阅**：只读工具 `recall_cards`。左栏角色可查自己、其他左栏角色与共用角色的卡；通道回合不下发该工具。
13. **摄入范围**：`owner_dm` → 主人卡 + 该角色卡；通道 → 共用角色卡。P3 起 `peer_dm` 与群聊也学：主人发过言 → 主人卡；每个发过言的左栏角色 → 各自的角色卡，从自己的视角学；同伴发言与助手发言同等对待，只有明确报告的工具结果算依据。

## 后果

- `KnowledgeCards`（`backend/app/engine/memory/cards.py`）是作用域卡片的唯一入口：取 store / resolver、面板操作、渲染、注入、查阅、删角色清卡。主人记忆仍经 `MemoryService`。
- `SessionMemoryObserve` 按会话决定镜头；通道会话开始打抽取标记，但只跑共用角色镜头，不产生主人卡。P3 起互通与群聊也打标记，按发言者决定镜头。
- 通道回合行为变更：默认不再注入主人记忆。
- 每段关段多一次 utility 模型调用；整理按作用域批量，有新增才跑（P1）。
- P2 人设进化的落地取舍：
  - 模型只输出逐条编辑（改写 / 插入 / 删除，各带理由与依据编号），由 `persona_edits.py` 逐条校验后按位置应用。依据门槛、主人手改优先（上次进化后主人改过的行受保护，删掉的文字不许加回）、墓碑、字数上限、密钥扫描都在代码里，不靠提示词。
  - 回退 = 用 `text_merge3` 把这一次改动从当前人设里反向合并掉；与之后的改动撞在同一处就拒绝。墓碑不另建表，从被回退的进化修订的 `meta` 推出。
  - 「已并入」不进卡片状态机，另存 `card_persona_marks`，按卡片正文哈希生效：卡片被修正即自动失效，不用追着人设或卡片的每次写入去同步。
  - 升格提议存 `card_proposals`；接受 = 把请求放进输入框，由主人发送。「主人明确要求」落在主人按下发送，而不是点了一个按钮后系统替主人去建。
  - P2 只进化左栏角色：通道的知识卡页签没有成长与人设历史，自动改动在那里既看不见也撤不回。
- P3 的落地取舍：
  - 通道页签补上成长与人设历史后，共用角色也进化。依据只认主人来源（面板亲手改过的，或主人来源跨 ≥2 段会话的）：外部卡被主人点过确认，只说明它是真的，不说明对外人设该这样说。通道不出升格提议。
  - 主人卡整理复用 `card_consolidation.py` 的引擎与校验，换一份整理方案（`OWNER_PROFILE`）：主人记忆的种类表、只读来源（主人亲定、主人要求记住）、种类只能取自原卡、敏感门禁。主人卡读写仍经 `MemoryService` 的 store 与 resolver，不建检索分区；成长日志与整理状态用固定作用域名 `owner`。
  - 主人卡的淡出不改规则，仍由 `MemoryMaintenanceJob` 按原衰减跑，只是把过期、作废、转回待印证写进成长日志。
  - 互通与群聊没有关段：会话上记一个已学到的消息序号，每次只抽其后的消息，另带前几条作指代参考；失败、中断的回复与系统消息一样跳过（消息落库即终态），所有视角都成功才推进。一个房间算一段会话，印证次数不因聊得久而虚高。

## 明确不采用

- 每角色私有文档库
- 一个提示词同时抽主人卡和角色卡
- 用关键词黑名单挡外部注入
- 外部对话驱动人设改写
- 自动建 Skill、自动写知识库文档
- 按通道实例（隐藏工作角色）各学各的
- 记录外部发送者个人画像
- 人设历史放进知识库 git
