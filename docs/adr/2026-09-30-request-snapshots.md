# ADR 2026-09-30：发送内容检查器记录实际请求，不再重拼

## 状态

已采纳（2026-09-30）。

## 背景

上下文容量圆环与「上下文构成」检查器的数据来自 `context_stats.py` 的**事后重拼**：按 system / memory / skill / history / tools / attachments 六类重新组装提示词、估算 token，再把与上次实测 `prompt_tokens` 的差额塞给其中一类。

提示词块越来越多（角色知识卡、按轮相关卡、工作托盘、预取上下文、角色协作、当前时间），重拼与编排层是两套代码，注定漂移：

- 【工作托盘】、预取上下文、【当前时间】、【相关知识卡】没有算进去；
- 工具循环里每次调用追加的工具往返与中途插话看不到；
- 【角色协作】的注入条件与编排层不一致；
- 【用户记忆】【角色知识卡】实际在 system 消息里，检查器却单列；
- 看不到消息结构和 `tools` 参数。

根因：检查器的数据源是推测，不是记录。

## 决策

1. **在发请求的那一刻记下请求体。** `LLMClient` 在 `_materialize` 之后、调用 provider 之前采集 `messages`、`tools` 与其余参数；只采主对话 `AgentToolLoop` 的调用（有会话与回合的采集上下文才记），后台调用不记。
2. **块标签在装配处打，是注解不是正文。** 装配代码给消息挂 `_parts`（种类、标签、原文），合并 system 时一并合并，发出前剥掉。采集时按实际正文依次定位各块，切成首尾相接的分段；定位不到的落入「未标注」。标签出错只影响展示，不改变发出去的内容。
3. **采集失败不影响回合。**
4. **落库前脱敏**：内嵌的 `data:` 图片数据换成占位，链接去掉签名参数。
5. **按消息哈希去重存储**，独立 SQLite（`kb/.kb/usage/requests.db`）。每会话保留最近 10 个回合的全部调用，另有全局上限；删会话即删。
6. **分项 token 仍是估算，总数是实测。** 各块估值等比缩放到实测 `prompt_tokens`，不再把差额整块塞给某一类。
7. **容量统计读最近一次调用**，删除重拼逻辑；不提供发送前预览。

## 后果

- 检查器显示的就是模型收到的内容：一条合并后的 system、历史、本轮 user、每次工具调用追加的往返与插话，以及工具定义；可逐回合、逐次调用翻看，也可看原始请求体。
- 新增提示词块时须在装配处打标签，否则检查器显示「未标注」——这是有意的可见信号，不靠文档约束。
- 请求快照含主人记忆与卡片正文等敏感内容，与会话同生命周期；不进知识库 git，不进检索。
- 新会话在第一次调用前没有构成可看；上线前的调用没有记录。
- 多一个 SQLite 文件；按消息去重后，存储量主要由历史与工具结果决定。
- 写入、淘汰、删会话都要在同一把锁里回收 blob，存储用可重入锁；`test_store_operations_do_not_deadlock` 限时守住，死锁会直接失败而不是卡住整批测试。
