# ADR 2026-09-19：官方《戒律》与本地修订三路合并

## 状态

已采纳（2026-09-19）

## 背景

未改过的官方《戒律》可随代码覆盖；一旦用户或助手在原文上演化，哈希对不上，官方升级就停住。
分区「本库补则」会把同一份家规拆成两套真相。需要像 git 一样整文件差异对比与合并，并让用户看见改了什么。

## 决策

1. **祖先快照** `.kb/precepts/stock.md` 记录上次已同步的官方正文，作为三路合并的 base。
2. **干净三路合并自动写回** 现行《戒律》；官方写入只走 `KnowledgeWriter`。活文件禁止出现冲突标记。
3. **有冲突则保持现行正文**，把冲突块与合并稿写入待确认会话。结构回退是「冲突处留当前」；AI 只填冲突块，不得削弱硬规则。用户确认后才落盘。
4. **没有祖先且正文已本地化**：两路审阅，不静默覆盖。未改过的旧官方稿（已知播种哈希）仍可自动换成新官方稿。
5. **保持** 只跳过这一版官方哈希，不把 stock 伪造成当前官方（stock 必须仍是 live 的祖先）。下一版官方仍用原 stock 做三路。
6. 版本回看复用知识库 git 修订，不另做一套只服务《戒律》的历史。

## 后果

- 官方升级与本地演化共用一份《戒律》
- 启动时 `PreceptsUpgrade.sync` 只做确定性合并；AI 在打开审阅时再跑
- Agent 在用户确认前仍读上一份完好戒律
