# ADR 2026-09-10：角色列表始终可见

**日期**: 2026-09-10  
**状态**: 已接受  
**决策者**: 用户明确要求

## 背景

在实现 Grok Bot 风格的三栏多角色 UI 时，需要决定角色列表的显示策略：
- 方案 A：单角色时隐藏角色列表，多角色时显示
- 方案 B：角色列表始终显示，无论角色数量

本 ADR 修正 [ADR 2026-09-09](2026-09-09-multi-role-shell.md) §2 中「单角色时不渲染角色列表」的设计决策，保留其余多角色底座设计。

## 决策

**采用方案 B：角色列表始终显示，即使只有一个角色。**

## 理由

### 1. UI 一致性
- 用户体验不会因角色数量变化而产生布局跳变
- 降低认知负担：用户无需适应两种不同的界面布局

### 2. 视觉清晰
- 当前活跃角色始终有明确的视觉位置和高亮状态
- 提供清晰的「你在和谁对话」的上下文提示

### 3. 实现简洁
- 无需条件渲染逻辑
- 减少边界 case（例如删除角色导致从多角色变单角色时的 UI 切换）
- 前端组件结构更简单

### 4. 符合参考设计
- Grok Bot 的三栏布局中，左栏（agent/routine 列表）是固定存在的结构元素
- 保持与视觉参考的一致性

### 5. 扩展友好
- 未来添加角色管理功能（重命名、删除、排序）时，固定的角色列表区域是自然的交互入口
- 为多用户场景（团队角色、共享角色）预留清晰的 UI 层次

## 替代方案

### 方案 A：单角色时隐藏角色列表

**优点**：
- 单角色场景下节省屏幕空间，聊天区更宽

**缺点**：
- UI 不一致，用户困惑
- 需要额外的切换逻辑和动画
- 活跃角色的视觉提示不明确
- 增加开发和维护成本

## 后果

### 正面
- UI 实现简单可靠
- 用户体验一致
- 代码可维护性高

### 负面
- 单角色用户可能认为左侧角色列表「浪费空间」
  - 缓解措施：左栏下半部分是知识库树，仍然有实用功能；整体三栏布局符合现代 app 设计惯例

## 实现注意事项

- `RoleList` 组件**不检查** `roles.length === 1` 来决定是否渲染
- 任何文档中提到「单角色时隐藏角色列表」的描述均已废弃，以本 ADR 为准
- 产品文档 `docs/product/multi-role.md` 已更新，明确此设计决策
