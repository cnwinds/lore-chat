# ADR 2026-10-02：统一上下文视图 `lore://`

## 状态

已采纳（2026-10-02），分步实施（见「落地顺序」）。改动 [ADR 2026-09-28](2026-09-28-role-knowledge-cards.md) 的两处：主人记忆建检索分区（原 P3「不建检索分区」），`recall_cards` 由通用读工具取代（原决策 12，可见规则不变）。

## 背景

模型现在读取上下文要用七个工具，各管一种存储，各写一套可见规则：

| 工具 | 读什么 | 可见规则 |
|---|---|---|
| `search_kb` | 知识库 + 会话 | 会话命中强制为当前会话的归属角色 |
| `read_doc` / `read_doc_meta` | 知识库文件 | 无（内部路径除外） |
| `list_kb_structure` | 知识库整棵树（只列 Markdown 与文本，每目录最多 15 个） | 无 |
| `read_conversation_context` | 会话原文 | 无 |
| `recall_memory` | 主人记忆（子串匹配） | 无 |
| `recall_cards` | 角色 / 人设卡 | 通道回合拒绝 |

问题有两类：

1. **可见规则分散，已经漏了。**
   - 通道回合仍下发 `recall_memory`，外部来访者可以诱导模型读出主人记忆，实例的主人记忆开关挡不住；
   - `read_conversation_context` 给了会话 id 就读，不查角色和来源；
   - 通道里每个外部会话线程一个会话，都挂在同一个隐藏角色下，`search_kb` 按「当前角色」过滤会话命中，于是来访者 A 的对话能被来访者 B 的回合检索到；
   - 工具执行时不校验本回合是否下发过该工具，模型输出未下发的工具名照样执行。
2. **没有范围这个概念。** 不能只在某个目录里检索，也不能一次查「知识库 + 某角色的会话」；主人记忆只能子串匹配。

调研 OpenViking 后的取舍：借它「一切上下文是一棵可寻址的树、用目录范围限定检索」的思路；不做目录级 L0/L1 摘要（后台同步维护代价大，卡片 + 检索已覆盖「找得到」与「去过的地方记得住」）；不做目录递归检索（OpenViking 自己已撤掉）。

## 决策

### 1. 单根目录树

```text
lore://
  kb/<知识库相对路径>
  conversations/
    dm/<角色>/<会话id>/<消息id>           主人与左栏角色的私聊
    rooms/<会话id>/<消息id>               角色互通与群聊
    channels/<实例id>/<会话id>/<消息id>   通道会话
  memory/
    owner/<种类>/<id>
    role/<角色>/<种类>/<id>
    persona/<人设>/<种类>/<id>
```

- **这是寻址视图，不是新存储。** 真相照旧：知识库在 git 文件，会话在会话库，记忆与卡片在 `memory.db`。物理目录不动。
- **会话归类**按会话库字段确定，不随回合变化：`kind=owner_dm` 且非通道来源 → `dm/<role_id>/`；`kind` 为 `peer_dm` / `group` → `rooms/`；通道来源 → `channels/<channel_instance_id>/`。隐藏工作角色（`api_` / `ext_` 前缀）不出现在 `dm/` 下。
- **种类段**：主人记忆用主人画像的种类（identity / preference / goal / project / workflow / constraint），角色与人设卡用卡片种类（domain / owner_context / practice / lesson / audience）。
- **规范写法用 id。** `<角色>` / `<人设>` 段还接受两种别名：`~`（当前应答角色；通道回合里 `memory/persona/~` 是本实例的人设），以及在可见范围内唯一的名字。返回结果一律写回规范 id 形式。会话、消息、卡片只接受 id。
- **简写与旧写法。** 不带 `lore://` 的相对路径就是 `lore://kb/` 下的路径；`conversation://<会话>[/<消息>]` 永久作为别名，按会话库解析成规范地址。目录 URI 以 `/` 结尾；前缀匹配按整段，`kb/技能` 不匹配 `kb/技能维护`。

### 2. 可见范围由回合算出，路径只能收窄

每个回合由会话来源、应答角色、通道实例配置算出可见根集合。模型给的每个路径必须落在某个可见根之内，否则**整次调用报错**并指出越界的路径，不返回部分结果，免得模型把「没权限」读成「没找到」。

| | 主人回合（网页私聊、互通、群聊、例行任务、无会话的 API） | 通道回合 |
|---|---|---|
| `kb/` | 全部（内部路径除外；`系统/` 可读，本来就不进索引） | 同左 |
| `conversations/dm/` | 全部左栏角色 | 不可见 |
| `conversations/rooms/` | 全部 | 不可见 |
| `conversations/channels/` | 不可见 | 只有当前会话 |
| `memory/owner/` | 可见 | 仅实例开了 `include_owner_memory` |
| `memory/role/` | 全部左栏角色 | 不可见 |
| `memory/persona/` | 全部 | 只有本实例的人设 |

主人回合里一个角色可以看其他左栏角色的私聊（全是主人自己的数据，与卡片的跨角色查阅一致）；默认检索范围仍只是本角色，跨角色要显式写路径。通道会话在主人回合里暂不可见，要开放须另行决定。

### 3. 三个读工具取代七个

| 新工具 | 取代 |
|---|---|
| `search(query, paths?, k?, ts_after?, ts_before?, cursor?)` | `search_kb`、`recall_memory`、`recall_cards` |
| `read(uri?, uris?, offset?, intent?, limit?, before?, after?, include_sources?)` | `read_doc`、`read_doc_meta`、`read_conversation_context` |
| `list(uri?, depth?, pattern?, type?, ts_after?, ts_before?, cursor?)` | `list_kb_structure` |

`read_last_tool_results` 读的是上一轮工具结果，不属于任何命名空间，保留。写工具一个不动。

**`search`**

- `paths` 可以给多个，例如 `["lore://kb/", "lore://conversations/dm/通用助手/"]`；互相包含的只留范围大的。不给时：主人回合是 `kb/` + `conversations/dm/~/`，通道回合是 `kb/`。当前会话默认排除，路径里显式写到它才算进来。
- 知识库与会话的命中照旧融合成一个列表（`Retriever` 四路 RRF、知识库强命中时压缩会话候选、门控）；记忆卡片太短、分数不可比，单独放在 `memory` 组里返回，不分页，最多 10 条。
- `ts_after` / `ts_before` 只作用于会话命中。翻页游标绑定规范化后的路径集合与查询。
- 每条命中带 `uri` 与 `kind`，原有字段（`sources`、`provenance_groups` 等）保留。

**`read`**：按 URI 指向的东西返回，详见第 4 条（知识库文件）与下面两项。

- 会话：`…/<会话id>/` 读尾部（同原「省略 message_id」），`…/<会话id>/<消息id>` 读该消息前后 `before` / `after` 条（各 0–10，默认 2）。脱敏、字数上限同原工具。
- 记忆：返回正文、种类、来源、状态；主人记忆 `include_sources=true` 时附出处（敏感条目不给原文，同原 `recall_memory`）。只读已确认条目，与原 `recall` 一致。
- 目录 URI 一律报错，提示用 `list`。
- 一次读多个：`uris` 最多 8 个，与 `uri` 同给时合并去重；超出的不读，在结果里列出。读之前先对全部地址做可见范围检查，有一个越界就整次报错（同第 2 条）；不存在、是目录等错误只标在该项上，其余照读。每项按 `intent` 的窗口截取，全部合计不超过硬上限，预算用完的项标出并给续读位置。`offset` 只对单个 `uri` 生效。每项都算「已读」（编辑前必读、Skill 激活都认）。

**`list`**：目标是让模型一次拿到够用的目录信息，少翻页、少逐层下钻、少因调错对象重来。

- `lore://` 列出本回合可见的顶层；知识库目录列子目录（带子项数）与文件（带 `kind`，文档带标题，文本与二进制带大小，二进制带类型），受保护路径标出。
- 展开：`depth` 默认 1，最大 5，传非数字按默认处理；顶层同样按 `depth` 展开。`depth=1` 列全这一层，超过 200 项给游标。`depth>1` 按层从上往下展开，单次最多 200 项，不翻页：先保证上层完整；一个目录要么整个展开（全部子目录加最多 20 个非目录条目），要么不展开，放不下就跳过它、继续展开后面的目录。`expanded` 只表示「它的子项在本次结果里」：因预算没展开的目录标 `expanded=false` 并带子项数，模型直接对它下钻；到了深度上限的目录同样是 `expanded=false`，但不算「未展开」。文件、会话、记忆条目这类非目录条目每个目录最多列 20 个，其余只记数（`omitted_files`），子目录总是列出。起点目录自己没列全时另计 `unlisted`，提示用 `depth=1` 加游标看全。
- 筛选：`pattern` 是名称或标题的通配（不区分大小写，如 `*.pdf`、`*合同*`），不带通配符时按包含匹配；`type` 取 `dir` / `doc` / `text` / `binary` / `conversation` / `memory`。给了任一筛选时，在 `depth` 范围内递归匹配（此时 `depth` 省略按最大），只返回命中项，按树序平铺，超过 200 项给游标。`type=dir` 就是只看结构，规划新路径时用。
- `ts_after` / `ts_before` 按最后活动时间筛会话；给了时间范围就只返回范围内的会话，目录、文件、记忆没有这个时间，不命中。
- `conversations/dm/` 列可见角色及会话数；`dm/<角色>/`、`rooms/` 按最近活动倒序列会话（标题、最后活动时间、条数）。上一会话段由此取得，不另设别名。
- `memory/` 下逐层列作用域、种类（带条数）、条目（正文预览）。
- 对文件、会话、记忆条目调 `list` 不报错：返回该项自身信息（类型、大小、标题、条数等），并提示读内容用 `read`。该项不存在时与 `read` 一样报不存在，不拼一个假条目。
- 知识库地址是目录还是文件以磁盘为准，`read` 与 `list` 都不看结尾斜杠；返回的 `uri` 一律是规范的 `lore://` 地址。
- `summary` 写明是否列全：未展开的目录数、按每目录上限省略的条目数、起点未列出的项数、是否还有下一页。

### 4. 知识库三类文件，按后缀确定性判定

| 类型 | 判定 | `read` | 检索 | 写入（不变） |
|---|---|---|---|---|
| 文档 | `.md` | 解析掉 `<<<LORE_META` 元数据头；正文按窗口返回并附大纲；元数据（title / tags / source 等）作为结构化字段一并返回 | 只索引正文 | `write_doc` / `edit_doc` / `update_doc_meta`，元数据头只由 `KnowledgeWriter` 写 |
| 文本 | `is_kb_text_file` 白名单 | 原文按窗口返回 | 抽取文本 | `write_kb_file` |
| 二进制 | 其余 | 不解码，返回类型与大小；`extract_text` 能抽取的（PDF、Office 等）返回抽取文本并标明 `extracted` | 抽取文本挂原路径 | 导入、`publish_from_sandbox`、`generate_image` |

- 文档没有「原始读」：模型看不到、也写不进元数据头。
- `read` 文档与文本时照旧登记编辑前必读（`DocReadGuard`，按知识库相对路径）。
- 写工具的路径参数也接受 `lore://kb/…`，经同一个规范化函数转成知识库相对路径；`conversations/`、`memory/` 一律拒绝写。`summarize_conversation` 的会话参数接受 `lore://conversations/…` 与旧 `conversation://`。

### 5. 路径编译到分区检索底座

| 路径 | 底座查询 |
|---|---|
| `kb/<前缀>` | `kb:main` + 组前缀（组 = 文档路径） |
| `conversations/dm/<角色>/` | `conv:main` + `conversation_id IN（该角色私聊会话）` |
| `conversations/rooms/`、`channels/<实例>/<会话>/` | `conv:main` + `conversation_id IN（…）` |
| `memory/owner/` | `cards:owner`（新分区） |
| `memory/role/<角色>/`、`persona/<人设>/` | `cards:role:<id>` / `cards:persona:<id>`（已有） |
| 末尾种类段 | 再加 `kind` 等值过滤 |

底座补两样能力，都不需要重建索引：

- **组前缀过滤**（多个前缀取并集）：全文在 SQL 里按 `grp` 区间过滤（已有 `(partition, grp)` 索引）；向量侧与现有范围过滤同法，扩大候选后按条目的组回查过滤。
- **`in` 过滤算子**：全文用 `json_extract … IN (…)`，向量交给 Chroma `$in`。会话 id 集合在查询时从会话库算出，可见性因此天然落在集合里；不往条目元数据里加角色字段，因为元数据进内容哈希，改了会让全部会话块重嵌。集合超过 1000 个会话时退回命中后回查过滤。

**主人记忆检索分区** `cards:owner`：与角色卡同族同分词，只索引已确认条目，写入点对账加每小时、启动、`reindex_all` 全量兜底；命中必须回源到 `memory.db` 仍是已确认的主人记忆，渲染用库里的当前文本。

### 6. 引用链接

回复里引用一律用 `lore://`：`[标题](lore://conversations/dm/<角色>/<会话>/<消息>)`、`[文档](lore://kb/路径.md)`。前端链接渲染统一解析：会话 → 跳转会话，知识库 → 打开文档，记忆 → 静态标签（本期不跳转）。旧 `conversation://` 继续可点。【上一会话段】指针改用新写法。

### 7. 执行时校验工具是否下发

工具循环只执行本回合下发过的工具，其余返回 `tool_not_offered` 错误，不派发。沙箱确认后的代跑走 `PendingResolver`，不经工具循环，不受影响。

## 落地顺序

0. **安全热修**（不依赖后续步骤，可单独发 patch）：第 7 条；通道回合不下发 `recall_memory`；`read_conversation_context` 按第 2 条的会话可见规则校验；通道回合的 `search_kb` 不返回其他会话的命中。
1. **底座与解析层**：组前缀与 `in` 过滤；`Retriever` 接受知识库前缀与会话 id 集合（原 `scope` 参数保留给内部调用方）；`cards:owner` 分区；URI 解析、别名、可见范围、路径编译（新包 `backend/app/engine/context_view/`）。只加代码，不改工具。
2. **工具切换**：一次性上线 `search` / `read` / `list`，删除七个旧工具；同步派发、工具目录、只读集合、通道排除表、时间线查询提取、Skill 激活识别（`read` 与历史里的 `read_doc` 都认）、编辑前必读、写工具路径规范化、【上一会话段】指针。
3. **提示词、前端与文档**：工具描述；官方《戒律》种子稿把 `search_kb` 改为 `search`，旧稿哈希记入已取代集合，现行稿走 [ADR 2026-09-19](2026-09-19-precepts-three-way-upgrade.md) 三路升级；前端 `lore://` 链接、新工具的标签与工具卡（旧工具名标签保留，历史时间线照常显示）；CONTEXT.md、ADR 索引、CHANGELOG。
4. **减少多余调用**（2026-10-02 补充）：`list` 的按层展开与预算、筛选、按时间列会话、单项不报错；`read` 一次读多个地址。

## 后果

- 读工具从七个降到三个，可见规则只在解析层写一次。
- 通道回合的三处泄露在第 0 步关掉；主人回合的跨角色会话读取由「检索拒绝、原文放行」统一为「默认本角色、显式可读全部左栏角色」。
- 主人记忆检索从子串匹配升级为二字组全文 + 向量；首次启动后台全量对账一次。
- 模型提示词与历史时间线里会同时出现新旧工具名：历史照常渲染，Skill 激活两种都认。
- 向量侧的组前缀过滤靠扩大候选，范围很窄而库很大时可能召回不足；出现时再给块加祖先目录元数据。

## 明确不采用

- 目录级 L0/L1 摘要：后台同步维护代价大
- 目录递归检索与分数传播：OpenViking 自己已撤掉
- `list` 不设上限的全量递归：知识库一大就撑爆上下文；用按层预算加「未展开」标记，让模型定点下钻
- `memory://` 可写：出处、墓碑、只读不变式只在 `SlotResolver` / 后台流程里成立；`KnowledgeWriter` 同理
- 三个独立 scheme（`kb://`、`conversation://`、`memory://`）：多一条区分轴，跨命名空间检索要拼两种前缀
- 裸绝对路径 `/kb/…`：知识库里可能有顶层目录叫 `memory`，与相对路径简写冲突
- 记忆卡片与文档、会话混排成一个列表：长度差两个数量级，分数不可比
- 往会话条目元数据里加角色字段：内容哈希变化会触发全部会话块重嵌
- 主人回合默认检索全部角色的会话：保持今天的默认范围，跨角色须显式
