# ADR 2026-09-29：文档库与会话迁入分区检索底座

## 状态

已采纳并落地（2026-09-29）。承接 [ADR 2026-09-29 分区检索底座](2026-09-29-partitioned-retrieval.md) 第 10 条的阶段 B。旧索引文件的清理留待下一次发版。

## 背景

阶段 A 已让角色知识卡用上底座。文档库与会话仍走旧栈：`FullTextIndex` / `ConversationFTS`（`trigram`）、`VectorIndex` / `ConversationVector`（Chroma `kbs` / `conversation_chunks_v2`），由 `Retriever` 四条通道拼接。旧栈的问题：

- 2 个汉字的检索词在 `trigram` 下建不出匹配，只能退到不排序的 `LIKE`；
- 嵌入模型不入账，换模型后旧向量与新查询不可比，却照样参与排序；
- 一次检索嵌入两次（文档、会话各一次）；
- 两套检索并存，分词、降级、同步策略各写一份。

## 决策

1. **对外契约不变。** `Retriever.search` 的入参与 `SearchPage` 字段、`search_kb` / `search_conversations` / 工作区搜索的输出都不改。内部按文档、会话两族各跑一次底座查询，第二次复用第一次的查询向量。四路 RRF 权重、「文档强命中则压缩会话候选」、强命中门控、分页游标都保留。
2. **分区与分组。**
   - 文档库只有一个分区 `kb:main`，以文档路径为组，一个块一条，块 id 沿用 `{路径}::{序号}`；
   - 会话只有一个分区 `conv:main`，以 `{会话}/{消息}` 为组，块 id 沿用旧格式；
   - 底座新增「组」这一层：按组全集对账、按组删除、按组前缀删除，对应「改一篇文档」「改一条消息」「删一段会话」。
3. **系统层文档不进索引。** 《戒律》《心法》等系统目录下的文档写入时就不建索引，取代查询时的路径前缀排除（排除仍保留作兜底）。
4. **关键词查询保留分级。** 模型写的检索词仍按严格（AND）→ 放宽（OR）→ `LIKE` 三级回退，门控依据不变。每个词在底座里按同一套二字组分词编成短语，因此 2 字中文词成了有效检索词。自然语言整句（卡片按轮检索）仍走原来的 OR + 稀有词。
5. **元数据过滤进底座。** 会话按 `conversation_id`（等于 / 不等于）与时间（≥ / <）过滤：全文在 SQL 里过滤，向量等值条件交给 Chroma、范围条件在内存里过滤并扩大候选。说话角色过滤仍在 `Retriever` 里回查会话库。
6. **向量后台补。** 文档与会话写入时只同步写全文，向量标记待补，由后台限流补齐，新内容优先。会话派生任务 `index_vector` 不再自己嵌入。
7. **旧数据迁移。**
   - 启动后在后台线程执行：先从真相重建全文（文档从知识库文件，会话从会话库）；
   - 再从旧 Chroma 集合**沿用**旧向量：块 id 相同、文本逐字相同的才沿用，模型记为当前嵌入模型探测到的名字，与旧栈的隐含假设相同；
   - 探测不到模型时不沿用，交后台重嵌；
   - 每一族迁移完成就在底座里记下完成时间，不再重复。迁移期间检索可用，但结果可能不全。
8. **旧索引文件本次保留不删。** `fts.db`、`conversation_fts.db` 与旧 Chroma 集合不再读写，留作回退；下一次发版再清理。旧代码（四个旧索引类）在本阶段末删除。

## 后果

- 旧索引类及其单测删除；构造 `Indexer` / `Retriever` / `DerivationWorker` 的测试改用新的测试辅助函数。
- 首次启动新版本后，后台跑一次迁移。沿用成功时不产生嵌入费用；沿用失败的块由后台逐批重嵌，期间向量结果不全，全文照常可用。
- 回退到旧版本时，旧索引缺少迁移后新写入的内容，需要在旧版本里手动重建索引。
- `reindex_all` 改为重建底座的文档、会话、卡片三族，并记下迁移完成。
- 一次检索最多嵌入一次。

## 明确不采用

- 以文档路径作分区名：路径可含空格、可能超长，而且查询全库时要列出上千个分区
- 迁移时整库重嵌、不沿用旧向量
- 阻塞启动等迁移跑完
- 在旧类外面包一层兼容壳：两个旧对象各有路径，映射不到同一个底座
- 把关键词查询也改成整句 OR：模型写的关键词需要 AND 的精度
