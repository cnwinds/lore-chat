# ADR 2026-09-09：多角色底座与侧栏角色列表

## 状态

已采纳（2026-09-09）

## 背景

Lore 需要从「单助手 + 会话时间线」演进为：底层可多角色并行，默认仅一个通用角色（知识沉淀助手观感）；知识库与主人记忆全局共享。界面上若保留「会话列表 + 另挂角色条」，用户要同时理解两套导航。

## 决策

### 1. 产品模型

- **角色**为一等公民：名称、头像、系统提示词、（后续）定时任务；独立对话上下文与 turn 队列。
- **启动**有且仅有一个 `is_default` 通用角色；用户可再创建角色（设置或后续由通用角色工具创建）。
- **知识库全角色共享**读写；**记忆全局一套抽取**，覆盖所有角色会话，规则仍为关于主人 / 耐久性 / 语境保全。
- **心法 / 戒律**全局；角色 `system_prompt` 为叠加层，不复制戒律。
- **并行**：切换 UI 不取消其他角色 running turn。

### 2. 界面信息架构

- 侧栏上半由「会话时间分组列表」改为 **角色列表**。
- **仅 1 个角色时不渲染角色列表**（自动选中默认角色）；用户无需理解「多角色」。
- **≥2 个角色**时渲染列表，点击切换 = 进入该角色活跃线。
- **主列表只回答「哪个角色」**；「哪次聊天」交给：
  - 每角色 **活跃线**（连续窗口内自动续；窗外静默新话题）；
  - **会话搜索**与（后续）本角色历史次级入口；
  - 动作文案 **「新话题」**（在当前 `role_id` 下建 conversation）。
- 不设设置项「简单/高级」总开关；复杂度由角色数量决定。

### 3. 数据与注入

- `roles` 持久化；`conversations.role_id` 归属角色。
- 连续窗口 `continuity_idle_hours`（与记忆 `memory_session_idle_hours` 分离）。
- Agent 组装：`compose_rules()` + 角色 `system_prompt` + 内置 `SYSTEM_PROMPT` + `<user_memory>`。

## 后果

- 前端 [`Sidebar`](../../frontend/src/components/Sidebar.tsx) 对话区语义变为角色导航；会话时间线不再做主导航。
- 创建会话必须带（或默认填）`role_id`；打开产品恢复「上次角色 + 其活跃线」。
- 定时任务、对话创建角色、忙碌角标、本角色历史抽屉可后续迭代，不阻塞本 ADR 底座。

## 明确不采用

- 每角色私有知识库根或私有主人画像库（默认可共享检索）。
- 设置里的简单/高级模式开关。
- 单角色时仍展示一项「角色列表」。
