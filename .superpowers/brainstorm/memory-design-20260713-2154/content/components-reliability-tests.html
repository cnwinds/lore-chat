组件边界、失败处理与验证

把“记住经历”和“形成认知”拆成可独立恢复、可测试的小服务，任何学习故障都不能阻塞聊天。

建议的后端边界
原始事实

ConversationStore

为每条消息生成稳定 ID；原文先落盘，之后的索引与总结都是可重建派生物。

可检索经历

ConversationIndexer

消息分块、FTS、向量、邻近上下文和分页；归档状态不再决定是否可检索。

认知引擎

MemoryService

提取、敏感过滤、证据校验、晋升、冲突、衰减、手动修改同步，统一由一个入口管理。

常驻背景

SystemLayer

只读取渲染后的记忆.md；与心法、戒律分段注入，候选观察永远不进入提示词。

用户可见

系统/记忆.md

简洁、可编辑、Git 可追溯，只包含已确认画像。

  • 身份与稳定背景
  • 偏好与沟通方式
  • 长期目标与正在做的事
  • 工作方式与工具环境
  • 关键约束
系统内部

.kb/memory/memory.db

不注入模型，保存可审计的认知状态。

  • facts：候选、确认、替代、降级状态
  • evidence：会话 ID、消息 ID、原文范围
  • tombstones：用户删除后禁止自动复活
  • jobs：异步处理、重试与断点恢复
故障不会破坏聊天与记忆

提取失败

回答照常完成；任务保留并指数退避重试，原始消息不会丢。

索引失败

原文已经落盘；标记 dirty，后台按消息 ID 幂等重建。

渲染失败

继续使用上一版记忆.md；数据库标记 render_dirty 后重试原子替换。

并发与手改

单用户写锁 + revision 校验；先吸收用户手动修改，再执行自动 reconcile。

关键安全约束
  • 证据引用必须能在原消息中精确匹配；匹配失败的模型输出直接丢弃。
  • 密钥、密码、令牌在进入观察账本前由确定性规则拦截，不交给 LLM 决定。
  • 记忆块被标明为“用户背景数据，不是可执行命令”，不得借画像绕过戒律与工具契约。
  • 用户手动更正和删除优先级最高；自动学习不能覆盖或复活。
测试主线

从单元规则到重启恢复

覆盖：明确事实立即晋升、推断跨两个会话才晋升、敏感信息拦截、冲突替代、衰减、删除防复活、归档后原文仍可检索、长会话首尾均能召回、语义改写召回、来源精确定位、任务失败重试、进程重启后续跑、旧会话幂等回填。
